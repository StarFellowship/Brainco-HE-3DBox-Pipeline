# ⑥ 큰 객체(table 등) 전처리 + VLM 프롬프트 정리 — 진행 중 (VLM 실구동 남음)

**요구**: 탐지되지 않는 큰 객체를 전처리로 잡아 보고, 현재 카테고리 추출 프롬프트의
구성을 정리하고, VLM으로 segmentation용 Object Categories를 뽑는 프롬프트를 설계한다.

## 1. 왜 안 잡혔나 — 차단 지점 특정

실험으로 두 게이트가 순서대로 막는 것을 확인했다.

1. **화면 점유율 게이트**가 1차로 기각 (Brainco 20/20 프레임)
2. 그것을 풀면 **3D 최대변 0.8m 상한**이 2차로 기각 (14/16 프레임)

둘 다 조작 대상(수 cm~수십 cm)에 맞춰 둔 값이라, 폭 1m가 넘는 테이블은 애초에 통과할 수
없는 조건이었다. 근거: [구실험_게이트차단분석.json](구실험_게이트차단분석.json)

## 2. 대형 객체 전용 게이트 확정

table 외에 접시·의자·노트북·책상·바구니까지 넓혀 측정한 실측치로 조합을 훑었다.

| 화면 점유율 상한 | 3D 최대변 상한 | 통과 | 크기가 타당한 것 |
|---|---|---|---|
| 0.35 | 2.5m | 9 | 8 |
| **0.50** | **2.5m** | **13** | **12** |
| 0.70 | 2.5m | 14 | 12 |
| 0.97 | 3.0m | 14 | 12 |

**점유율 0.50 / 최대변 2.5m를 채택했다.** 더 풀어도 타당한 것은 늘지 않고 오검출만
들어온다. 게이트가 걸러낸 것은 바닥을 5.06m로 잡은 것과 화면의 59%를 차지한 이동조작 테이블 두 건이다.
반면 로봇 그리퍼를 의자로 본 오검출은 크기가 작아 게이트를 그대로 통과하며,
통과한 13건 중 유일하게 타당하지 않은 건이 이것이다 — 게이트가 아니라 검출 단계의 문제다.

이 값은 **대형 객체 라벨에만** 적용된다. 기존 15개 태스크는 각자의 설정을 그대로 쓰므로
코드 경로가 분리되어 있고, 이번 변경으로 영향을 받지 않는다.

산출물: [검증통과샘플/](검증통과샘플/) — 객체마다 2D 박스 / 픽셀 마스크 / 3D 박스 3종.
36장 중 육안 검증을 통과한 14장만 수록했다.
코드: [bigobj2.py](bigobj2.py) — 장면별 객체 검출·분할·3D 박스 산출.
위 게이트 표는 그 결과인 [검증통과샘플/결과요약.json](검증통과샘플/결과요약.json)을 조합별로 재집계한 것이다.

## 3. 프롬프트 정리와 VLM 설계

**현재 구성** — VLM이 아니라 수작업 지정이다. 데이터셋 지시문의 어휘에 상위 개념을
병기하는 규칙이며(예: `oreo snack package . plate .`), 15개 태스크 전수를 표로 남겼다.

**VLM 프롬프트 설계** — Qwen2.5-VL 기준으로 첫 프레임에서 네 갈래를 뽑도록 설계했다.
조작 대상 / 참조 물체 / 대형 배경 / 로봇 부위. few-shot 예시까지 작성 완료.

상세: [prompt-design.md](prompt-design.md)

## 4. 남은 것

VLM **실제 구동**은 모델 설치가 필요해 ⑧의 모델 교체와 함께 진행한다. 설치 후 15유닛에
돌려 수작업 정의와의 일치율을 측정하는 것이 검증 방법이다.
