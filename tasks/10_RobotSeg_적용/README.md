# ⑩ RobotSeg 논문 방법 직접 적용 — 완료 (2026-08-16)

**요구**: RobotSeg(CVPR 2026, SAM2 기반 로봇 분할 모델)를 우리 파이프라인 데이터에 직접
적용해 보고, 잘 안되면 원인을 분석하고 개선을 시도한다. '가능 여부'가 아니라
'품질 향상' 관점으로 평가한다.

## 설치와 실행

- 공개 모델 파일 `robotseg.pt`(165MB, SAM 2.1 Hiera-Tiny 백본)를 받아 서버에 설치.
  자동(automatic) 모드는 문구·클릭 없이 arm / gripper / robot 3종 mask를 만들어 준다.
- 우리 데이터 4개 영상(3인칭 머리 3개 + 1인칭 손목 1개, 각 220프레임)에 실행하고,
  현행 방식(SAM 2.1 + robot arm 문구)과 **같은 프레임을 나란히** 놓고 44프레임을
  상·중·하로 채점했다. 비교 이미지: [비교이미지/](비교이미지/)

## 채점 결과 (44프레임)

| 방식 | 상 | 중 | 하 |
|---|---|---|---|
| 현행 (SAM 2.1 + 문구) | 29 | 15 | 0 |
| RobotSeg 자동 모드 | 0 | 32 | 12 |

- RobotSeg는 3인칭에서 **오른팔을 거의 전 프레임 놓쳤고**, 다섯 손가락 손은 44프레임 중
  1프레임 빼고 못 칠했다. 쥔 물병을 팔에 포함시키는 오류도 있다.
- **원인은 학습 데이터의 도메인 차이다** — 학습 로봇 10종이 전부 "팔 하나 + 집게형
  그리퍼 + 3인칭"이라, 양팔 휴머노이드·다섯 손가락 손·1인칭은 본 적이 없는 형태다.
  논문에 휴머노이드/1인칭 평가는 없다(전문 확인).
- 강점도 확인: RobotSeg가 칠한 부분은 **배경으로 번지는 오류가 없다.** 현행 방식은
  범위는 넓지만 몸통 과잉 포함·배경 미끄러짐이 있다.

## 개선 시도 — 두 방식의 결합

RobotSeg의 box 프롬프트 모드에 우리 파이프라인이 찾은 왼팔·오른팔 box를 첫 프레임에
넣어 주자, 자동 모드에서 통째로 놓치던 **오른팔이 영상 끝까지 추적됐다**
([비교이미지/box프롬프트_양팔추적_f90.jpg](비교이미지/box프롬프트_양팔추적_f90.jpg)).
"우리 검출 + RobotSeg 추적" 결합이 실제로 동작한다.

**손에 대한 마지막 시도** — 손(gripper)에도 우리가 찾은 손 box를 직접 넣어 봤다.
결과는 [비교이미지/손box프롬프트_여전히실패_f90.jpg](비교이미지/손box프롬프트_여전히실패_f90.jpg):
손을 정확히 지목했는데도 **팔 전체를 칠하고 검은 다섯 손가락 손은 여전히 빠졌다.**
box로 위치를 알려줘도 안 되는 이유는, 이 모델이 배운 "gripper"가 집게형 2지 그리퍼라
다섯 손가락 손을 그리퍼로 인식하지 못하기 때문이다. 위치 문제가 아니라 학습한 형태의
문제이므로, 프롬프트로는 해결되지 않는다.

## 결론

우리 데이터 기준으로는 현행 방식이 우세하다. RobotSeg를 쓴다면 통째 교체가 아니라
우리 검출을 프롬프트로 넣는 결합 방식으로 팔 몸통 mask를 보강하는 용도가 적절하다.
