# ⑨ 로봇 팔·손 추출 + 모든 객체 추출 + 물체 간 상관관계 — 완료 (2026-08-16)

**요구**: 팔에 대해서도 3D Bounding Box와 segmentation 라벨(왼팔/오른팔/왼손/오른손 구분)을
저장하고, 화면에 보이는 물체 정보를 최대한 많이 추출하며, 물체 간 상관관계를 산출한다.
"task 대상만 추출"과 "보이는 모든 객체 추출"을 둘 다 실행해 잘 안되는 것과 이유를 조사한다.

## 1. 로봇 팔·손 추출

검출 문구에 robot arm, robot gripper를 추가해 팔과 손도 물체와 동일하게
`라벨 + 2D box + mask(COCO RLE 압축) + 3D Box`로 프레임마다 저장한다.

- **왼/오른 구분은 화면 위치 기준이다** — 같은 라벨이 2개 검출되면 화면 왼쪽이 left.
  검출 모델이 left/right의 의미를 알아듣지 못해 쓴 차선책이며, 팔이 교차하면
  좌우가 뒤바뀔 수 있다.
- 크기·위치 검사는 물체용 기준과 분리해 팔 전용 값(최대 1.5m 등)을 둔다.
  기존 물체 결과에는 영향이 없다.
- 결과: 머리 카메라 기준 팔 검출률 93~100% (예: GraspRubiksCube ep6 왼팔 220/220프레임).
  단, 은색 팔에서 mask가 배경으로 미끄러지는 프레임과 로봇 몸통 과잉 포함이 일부 있다.

구현: [`pipeline/multiobj.py`](../../pipeline/multiobj.py) (검출·좌우 부여·게이트),
러너 [`pipeline/run_sample10.py`](../../pipeline/run_sample10.py)

## 2. 모든 객체 추출 — 두 방식 비교

같은 에피소드를 (a) 대상만 / (b) 대상+참조물+배경물+로봇 부위 전부, 두 방식으로
각각 10에피소드 전량 돌렸다 (`MODE=task|all`).

**결과**: 278개 영상(에피소드×카메라)에서 나온 라벨은 24종 — 하나도 빠짐없이 문구에 미리
적어준 것들이다. Brainco만 볼 때 12종이던 것이 HE를 합쳐 24종이 됐지만, 이는 HE 작업이
다른 물체를 쓰기 때문에 우리가 적어준 목록이 길어진 것일 뿐이다. 화면에 보이는 다른
물건은 끝까지 하나도 나오지 않았다.

**원인**: GroundingDINO는 적어준 이름을 찾는 모델이지, 화면에 무엇이 있는지 스스로
알아내는 모델이 아니다. "보이는 모든 객체"를 뽑으려면 이름 목록 자체를 자동 생성해야
하며, VLM으로 첫 프레임에서 목록을 만드는 방안은 ⑥에서 설계해 두었다(모델 설치 필요).

**간섭 없음 확인**: 두 방식의 대상 검출률이 완전히 같았다(Brainco 208개 영상 평균 0.647 동일,
[분석/mode_ab_det.py](분석/mode_ab_det.py)). 대상 검출과 추가 객체 검출을
별도 단계로 분리한 설계 덕분이다.

## 3. 물체 간 상관관계

프레임마다 모든 물체 쌍의 3D 중심 거리 / 박스 표면 간격 / 위아래 / 접촉(표면 간격<5cm)을
계산해 `relations.json`으로 저장하고, 사람이 읽을 요약 `relations.txt`도 만든다.
구현: [`pipeline/relations.py`](../../pipeline/relations.py)

**활용 실증** — 대상과 손의 표면 간격이 5cm 미만으로 5프레임 이상 이어지는 구간을 뽑으면
"손이 물체를 잡고 있는 구간"이 된다. 머리 왼쪽 카메라 80개 영상 중 **79개에서 추출 성공**
([분석/grasp_span.py](분석/grasp_span.py)). 렌더와 교차 확인: PickDrink ep26의 90프레임
(왼손이 물병을 쥠)이 추출 구간 78~91에 정확히 포함된다. 에피소드를 "잡기 전 / 조작 중 /
놓은 후"로 자동 분절하는 데 쓸 수 있다. 간격이 추정 depth 기반이라 5프레임 미만
구간은 오탐 가능성이 있어 걸렀다.
