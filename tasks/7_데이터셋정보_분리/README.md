# ⑦ 데이터셋 정보 사용가능/불가 분리 + 입력 대체 검토 — 진행 중 (화각 보정 미달성)

**요구**: 파이프라인 과정에서 데이터셋 정보를 (사용 가능 / 불가능)으로 분리해 정리하고,
3D 박스의 높이·공간 정확도가 부족하므로 데이터셋의 카메라 변수와 depth를 파이프라인
입력으로 대체할 수 있는지 검토한다. 가능하면 결과를 비교한다.

## 1. 정보 3분류 (전수 실측)

두 데이터셋의 메타를 전부 읽어 분류했다. 상세는
[dataset-info-inventory.md](dataset-info-inventory.md).

| 구분 | 항목 |
|---|---|
| **지금 쓰는 것** | RGB, HE 실측 depth(mm), UniDepthV2가 추정하는 intrinsics |
| **있지만 안 쓰는 것** | HE LiDAR(`observation.lidar`, 프레임당 약 4,700점), IMU, odometry |
| **아예 없는 것** | 양쪽 모두 intrinsics·extrinsics, 카메라-LiDAR 캘리브레이션. Brainco는 depth도 없음 |

높이가 어긋나는 근본 원인은 마지막 줄에 있다. HE는 내부 파라미터가 없어 **화각 70°를
가정**하고 있는데, 이 값이 틀리면 3D 크기가 통째로 상수배 어긋난다.

## 2. 대체안 검토와 실측 결과

세 가지를 검토했고, 그중 유일하게 외부 실측 기준이 될 수 있는 LiDAR를 직접 시험했다.

**방법**: 같은 프레임에서 (1) LiDAR 점군의 지배 평면까지 거리와 (2) 실측 depth를 화각
가정으로 역투영한 점군의 지배 평면까지 거리를 각각 재고, 비율이 프레임 간 일정한지 본다.
화각이 맞다면 비율이 일정해야 하고, 그래야 보정 계수로 쓸 수 있다.

**결과** (에피소드 10개 · 60프레임, [LiDAR_화각검증/](LiDAR_화각검증/)):

| 가정 화각 | 비율 중앙값 | 변동계수 |
|---|---|---|
| 60° | 1.450 | 0.680 |
| **70° (현재)** | 1.288 | **0.512** |
| 75° | 1.245 | 0.494 |
| 80° | 1.237 | 0.638 |

**어느 화각에서도 변동계수가 0.49 아래로 내려가지 않는다.** 프레임마다 비율이 흩어진다는
뜻이므로 보정 계수로 쓸 수 없다. 원인은 두 센서가 같은 평면을 보지 않는 것이다 —
LiDAR는 방 전체를 훑어 거리 중앙값이 4.3m인 반면 깊이 카메라는 작업면을 봐서 1.7m다.
카메라-LiDAR 캘리브레이션이 없어 공통 평면을 지목할 방법도 없다.

**결론: 이 경로는 성립하지 않는다.** 선택지 하나를 근거와 함께 닫은 결과로 본다.
코드: [lidar_plane_check.py](lidar_plane_check.py)

## 3. 남은 두 후보와 다음 단계

| 후보 | 현 모듈에서의 한계 |
|---|---|
| 테이블 평면 RANSAC으로 박스 밑면 고정 | 평면을 찾을 기준 자체가 추정 depth라 오차가 그대로 전파된다 |
| 초점거리 추정 내장 depth 모델 (Depth Pro, MoGe-2) | 애초에 모델 교체를 전제로 한다 |

둘 다 현재 모듈 구성으로는 한계가 분명하다. 따라서 이 항목의 실질적 진전은
**⑧의 depth 모델 교체와 묶어** 진행한다. HE에는 실측 depth가 있어, 교체하는 즉시
정량 비교가 가능하다(현 기준선: 근접 43%, 중거리 21.7% 상대오차).
