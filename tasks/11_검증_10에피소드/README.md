# ⑪ 작업당 10에피소드 검증 — 잘된 것/하자 구분과 원인 분석 (2026-08-16)

**요구**: 데이터셋별·task별로 에피소드 10개씩 돌려 전체 모듈 통과가 멀쩡한 것과 하자가
있는 것을 구분하고, 하자는 어느 모듈에서 왜 생기는지 원인을 분석한다.

## 규모와 절차

- 영상 1개 = 에피소드 1개 × 카메라 1대. Brainco 8작업 × 10ep × 머리 2대(+손목 일부),
  HE 7작업 × 10ep × 1인칭 1대. 에피소드는 고정 시드(42) 무작위 표본.
- 절차: ① 전체 렌더 → ② 저장 기록을 코드로 훑어 하자 후보 추림 → ③ 후보마다 판정용
  정지컷 추출(498장) → ④ **전량 눈으로 보고 판정**. 수치만으로 판정하지 않은 이유:
  수치상 하자로 보여도 실제로는 정상인 경우(물체를 손에 쥐어 잠시 가려짐)가 많았다.

## 분류 기준

10에피소드 전부 깔끔 = **완벽** / 하자 에피소드 3개 이하 = **개선중** / 4개 이상 = **못함**.
일부 모듈에서만 생긴 하자도 하자로 센다. 판단 애매는 하자로 세지 않고 따로 표기.

## 결과 (머리·1인칭 카메라; 손목은 별도)

15작업 전부 판정 완료 — **완벽 5 / 개선중 4 / 못함 6**.

| 분류 | task |
|---|---|
| **완벽** (10ep 모두 깔끔) | GraspRubiksCube, PickDoll, PickTissues, deformable(HE), Tool_use(HE) |
| **개선중** (하자 3ep 이하) | HRI(HE) 1, Articulated(HE) 2, Locomanip(HE) 2, PickDrink 2 |
| **못함** (하자 4ep 이상) | Basic(HE) 5, Precision(HE) 5, PickApple 7, PickCharger 8, PickToothpaste 8, GraspOreo 9 |

두 데이터셋이 분류마다 섞여 나타난다 — 데이터셋 차이보다 **물체의 크기·색 대비**가 결과를 가른다.

상세 표(에피소드 수·하자 유형·애매 표기)는 [판정/판정표.md](판정/판정표.md),
영상별 전체 판정은 [판정/판정표_전체.json](판정/판정표_전체.json).

**요점**: 결과를 좌우하는 것은 물체의 크기·색이다. 크고 색 대비가 뚜렷한 물체는 완벽,
작거나 배경과 색이 비슷한 물체(오레오·충전기·치약)에서 하자가 몰린다.

## 하자 유형 → 원인 모듈

| 하자 | 영상 수 | 원인 |
|---|---|---|
| 물체를 옮기는 동안 박스가 못 따라감(빈 공간·엉뚱한 곳에 박스) | 42 | 1단계 검출 끊김 + 2단계 SAM 추적이 손·배경으로 미끄러짐 |
| 화면에 보이는 물체를 검출기가 놓침 | 39 | 1단계 GroundingDINO (작은 물체·배경과 비슷한 색) |
| 후처리가 실물 프레임을 잘못 자름 | 9 | 후처리는 "검출이 끊긴 이유"를 알 수 없음 (아래) |

- ghost(물체가 사라졌는데 박스가 남음)는 후처리로 34개 영상 1,205프레임 제거.
- **정직 보고**: 9개 영상에서는 제거 구간에 물체가 실제로 있었다(흰 충전기를 검출기가
  못 본 것을 "사라짐"으로 오인). 후처리·조건문으로 도달 가능한 상한이 여기까지이며,
  완전한 해결은 1단계 검출 모델 교체다.
